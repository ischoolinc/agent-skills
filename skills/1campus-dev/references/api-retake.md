# Retake API（重補修系統 API）規格

使重補修系統可與校務系統整合，取得學生重補修資料，並於重補修後寫回重補修成績
...

Base URL：`https://devapi.1campus.net`

完整的互動式 API 規格請參考 [Swagger 文件](https://devapi.1campus.net/doc/)。

---

## GET /api/retake/{dsns}/getRetakeStudent — 取得重補修學生及科目資料(不包含重讀、不計學分、學分數為0之成績)

### 參數

| 名稱 | 位置 | 類型 | 必填 | 說明 |
|------|------|------|------|------|
| dsns | path | string | 是 | 指定學校的主機名稱（例如 `h.demo.1campus.net`） |
| sampleMode | query | int64 | 否 | 因應這個呼叫測試的UI，在回傳資料量太大時，效能太差會跑死到的蠢問題，所以新增一個在使用此介面預覽時專用的欄位，就只會回傳少少資料，看看結構就好，程式裏頭千萬不要傳這個欄位。（例如 `sampleMode`） |

### 錯誤回應

- `401`：認證失敗或無權限

## POST /api/retake/{dsns}/setRetakeScore — 寫入學生重補修成績

寫入學生重補修成績 ## 重修成績擇優處理機制 系統實作重修成績擇優處理機制，確保學生永遠保留最好的重修成績： ### 處理邏輯 1. **前置判斷**：成績無變動或擇優保留舊成績的情況直接跳過處理 2. **後續處理**：成績有變動或擇優採用新成績，沿用原有邏輯 ### 處理案例 - **成績無變動**：112-2 重修 60 分 → 再次上傳 112-2 重修 60 分 → 不處理 - **擇優保留舊成績**：112-2 重修 60 分 → 113-2 重修 55 分 → 保留 60 分，記錄擇優保留 - **成績同分更新**：112-2 重修 60 分 → 113-2 重修 60 分 → 更新為 60 分（新學期） - **擇優採用新成績**：112-2 重修 50 分 → 113-2 重修 60 分 → 更新為 60 分 ### 日誌記錄 - **成績無變動**：不記錄（直接跳過） - **擇優保留舊成績**：記錄「重修成績 X 未採用（舊成績 Y 較優）」 - **成績更新**：記錄「重修成績由 X 更新為 Y」或「重修成績為 Y」

### 參數

| 名稱 | 位置 | 類型 | 必填 | 說明 |
|------|------|------|------|------|
| dsns | path | string | 是 | 指定學校的主機名稱（例如 `h.demo.1campus.net`） |

### Request Body

| 欄位名稱 | 類型 | 必填 | 說明 |
|----------|------|------|------|

### 錯誤回應

- `401`：認證失敗或無權限
